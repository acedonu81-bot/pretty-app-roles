# UX Fixes — Mensajes, Contacto, Ticker, Google Auth, Promesa Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix 6 production UX problems: ticker estático cortado, módulo mensajes con fondo oscuro, botones de contacto duplicados/inservibles en ficha pública, contacto mobile cluttered en directorio, Google OAuth roto, y eliminar el bloque "Modo Promesa / Última Llamada".

**Architecture:** Cambios contenidos en ficheros existentes — no se crean nuevas páginas ni rutas. Cada tarea es independiente y deployable por separado. El ticker mueve su `@keyframes` al CSS global para evitar que re-renders de React invaliden la animación. El módulo mensajes adopta la paleta light (#fff / #f9f8f6) del resto de la app. El contacto se consolida en un único punto de entrada. El bloque Promesa se elimina de tres ficheros de UI.

**Tech Stack:** React + TypeScript + Vite, Tailwind v3.4, Supabase JS client, Lucide React.

## Global Constraints

- Paleta light de XPEAK: fondo principal `#f9f8f6`, blanco `#ffffff`, dorado `#D4AF37`, texto primario `rgba(22,20,18,0.88)`, texto secundario `rgba(22,20,18,0.45)`.
- No emojis, no íconos "pedorros" — solo Lucide React donde ya se usan.
- Sin nuevas dependencias npm.
- No borrar el rol `rookie` ni la función `VoteButton` — solo eliminar los bloques de UI que los exponen al usuario.
- `npx vitest run` debe pasar en todo momento (11 tests existentes).
- Deploy final: `git push https://github.com/acedonu81-bot/pretty-app-roles.git main` + `npx vercel@latest --prod`.

### Task 1: Fix ActivityFeedWidget — ticker se corta cuando está estático

**Problema raíz:** El `@keyframes xpeakActivityTicker` está dentro de un `<style>` JSX inline. Cada re-render de React puede hacer que el browser re-evalúe el CSSOM y resetee la animación en curso, dejando la pista en mitad del ciclo (se ve "cortada"). Además, el div animado usa `position: absolute` sin `width: max-content` explícito, por lo que `translateX(-50%)` puede no apuntar al punto correcto del loop.

**Files:**
- Modify: `src/index.css` — añadir keyframe global
- Modify: `src/components/dashboard/ActivityFeedWidget.tsx` — quitar `<style>` inline, añadir `width: max-content`, aumentar altura de carril

**Interfaces:**
- No new exports. `Lane` y `ActivityFeedWidget` son internos.

- [ ] **Step 1: Añadir el keyframe a index.css**

Abre `src/index.css` y añade al final del fichero (después de todas las reglas existentes):

```css
/* Ticker de actividad reciente en el dashboard */
@keyframes xpeakActivityTicker {
  0%   { transform: translateX(0); }
  100% { transform: translateX(-50%); }
}
```

- [ ] **Step 2: Actualizar ActivityFeedWidget.tsx**

Reemplaza el contenido completo de `src/components/dashboard/ActivityFeedWidget.tsx` con:

```tsx
import { Sparkles, MapPin, MessageCircle } from 'lucide-react';
import { useActivityFeed, ActivityItem } from '@/hooks/useActivityFeed';

function minutesAgo(iso: string): number {
  return Math.floor((Date.now() - new Date(iso).getTime()) / 60_000);
}

const Chip = ({ item }: { item: ActivityItem }) => {
  const isNew = item.kind === 'signup' && minutesAgo(item.createdAt) < 15;
  return (
    <div
      className="flex-shrink-0 flex items-center gap-2 px-3 py-1.5 rounded-full"
      style={{ background: '#f9f8f6', border: '1px solid rgba(0,0,0,0.06)' }}
    >
      <div className="relative flex-shrink-0">
        <div className="w-6 h-6 rounded-full flex items-center justify-center text-[10px] font-black"
          style={{ background: `${item.roleColor}22`, color: item.roleColor, border: `1px solid ${item.roleColor}55` }}>
          {item.kind === 'contact' ? <MessageCircle size={11} /> : item.name.charAt(0).toUpperCase()}
        </div>
        {isNew && (
          <span className="absolute -bottom-0.5 -right-0.5 w-2 h-2 rounded-full"
            style={{ background: '#22c55e', border: '1.5px solid #fff' }} />
        )}
      </div>

      {item.kind === 'contact' ? (
        <span className="text-xs font-bold whitespace-nowrap" style={{ color: 'rgba(22,20,18,0.8)' }}>{item.text}</span>
      ) : (
        <>
          <span className="text-xs font-bold whitespace-nowrap" style={{ color: 'rgba(22,20,18,0.88)' }}>{item.name}</span>
          <span className="text-[10px] font-bold px-1.5 py-0.5 rounded-full whitespace-nowrap"
            style={{ background: `${item.roleColor}18`, color: item.roleColor }}>
            {item.roleLabel}
          </span>
          {item.zone && (
            <span className="text-[11px] flex items-center gap-0.5 whitespace-nowrap" style={{ color: 'rgba(22,20,18,0.4)' }}>
              <MapPin size={9} /> {item.zone}
            </span>
          )}
        </>
      )}
    </div>
  );
};

// Carril de marquee continuo: los items se renderizan dos veces seguidas y el
// track se anima -50% de su propio ancho (= exactamente un juego de items),
// creando un loop perfecto sin huecos. El keyframe está en index.css global
// para que los re-renders de React no invaliden la animación en curso.
const Lane = ({ items, durationSeconds }: { items: ActivityItem[]; durationSeconds: number }) => {
  if (items.length === 0) return null;
  return (
    <div className="overflow-hidden h-11">
      <div
        className="flex items-center gap-3 will-change-transform"
        style={{
          width: 'max-content',
          animation: `xpeakActivityTicker ${durationSeconds}s linear infinite`,
        }}
      >
        {items.map((item, i) => <Chip key={`a-${item.id}-${i}`} item={item} />)}
        {items.map((item, i) => <Chip key={`b-${item.id}-${i}`} item={item} />)}
      </div>
    </div>
  );
};

const ActivityFeedWidget = () => {
  const { items } = useActivityFeed();

  if (items.length === 0) return null;

  const laneA = items.filter((_, i) => i % 2 === 0);
  const laneB = items.filter((_, i) => i % 2 === 1);

  return (
    <div className="mx-4 md:mx-6 mt-4 rounded-xl px-4 py-3 overflow-hidden"
      style={{ background: '#ffffff', border: '1px solid rgba(212,175,55,0.2)' }}>
      <div className="flex items-center gap-2 mb-3">
        <Sparkles size={13} style={{ color: '#D4AF37' }} />
        <span className="text-xs font-black tracking-wider" style={{ color: '#D4AF37' }}>
          ACTIVIDAD RECIENTE
        </span>
      </div>
      <div className="flex flex-col gap-2">
        <Lane items={laneA} durationSeconds={Math.max(20, laneA.length * 7)} />
        <Lane items={laneB} durationSeconds={Math.max(20, laneB.length * 7)} />
      </div>
    </div>
  );
};

export default ActivityFeedWidget;
```

Cambios clave respecto a la versión anterior:
- Eliminado `<style>` inline con `@keyframes` (ahora en `index.css` global).
- `Lane` ya no usa `position: absolute` en el track — el track es `display: flex` normal con `width: max-content` explícito, por lo que `translateX(-50%)` apunta exactamente a la mitad del contenido.
- La altura del carril sube de `h-10` (40px) a `h-11` (44px) para que los chips no se recorten.
- `overflow-hidden` en el carril padre en lugar de `relative overflow-hidden` (ya no se necesita `relative` sin el hijo absoluto).

### Task 6: Fix Google OAuth — diagnóstico, configuración y código defensivo

- [ ] **Step 2: Actualizar Auth.tsx — redirectTo explícito**

Lee `src/pages/Auth.tsx`. Localiza `handleGoogleSignIn`:

```tsx
const handleGoogleSignIn = async () => {
  setGoogleLoading(true);
  const { error } = await supabase.auth.signInWithOAuth({
    provider: 'google',
    options: { redirectTo: `${window.location.origin}/auth` },
  });
  if (error) { toast.error('Error al conectar con Google'); setGoogleLoading(false); }
};
```

Reemplaza por:

```tsx
const SITE_URL = import.meta.env.VITE_SITE_URL ?? window.location.origin;

const handleGoogleSignIn = async () => {
  setGoogleLoading(true);
  const { error } = await supabase.auth.signInWithOAuth({
    provider: 'google',
    options: { redirectTo: `${SITE_URL}/auth` },
  });
  if (error) {
    console.error('[Auth] Google OAuth error:', error);
    toast.error(
      error.message.includes('provider') || error.message.includes('OAuth')
        ? 'Google login no está configurado. Usa email y contraseña.'
        : 'Error al conectar con Google. Inténtalo de nuevo.'
    );
    setGoogleLoading(false);
  }
};
```

La constante `SITE_URL` se declara DENTRO del componente `Auth` (no a nivel de módulo) para respetar el ciclo de vida de los hooks — pero como no es un hook, puede declararse fuera si el componente es funcional. Ponla justo antes de `handleGoogleSignIn` dentro del componente.

- [ ] **Step 3: Checklist de configuración externa (ejecutar manualmente)**

Estos pasos son fuera del código y deben hacerse en el dashboard de Supabase y Google Cloud Console:

**En Supabase Dashboard (https://supabase.com/dashboard):**
1. Proyecto XPEAK → Authentication → URL Configuration
2. **Site URL**: debe ser `https://xpeak.es`
3. **Redirect URLs**: añadir `https://xpeak.es/auth` si no está

**En Supabase Dashboard → Authentication → Providers → Google:**
4. Google debe estar **habilitado** (toggle ON)
5. Copiar la URL de callback de Supabase: algo como `https://<ref>.supabase.co/auth/v1/callback`

**En Google Cloud Console (https://console.cloud.google.com):**
6. APIs & Services → Credentials → OAuth 2.0 Client IDs
7. En "Authorized redirect URIs" añadir la URL de callback de Supabase del paso 5
8. En "Authorized JavaScript origins" añadir `https://xpeak.es`

Sin estos pasos de configuración, el código solo mostrará "Error 400: redirect_uri_mismatch" o similar desde Google.
